# 009 — Расчёт и выдача слотов

Статус: выполнено 06.10.2026 в согласованной границе публичной выдачи;
ревью и независимая проверка пройдены. Роль: backend. Зависит от: 005, 007, 008.

## Предварительная проверка 06.10.2026

После `git fetch origin --prune` все три зависимости входят в `origin/dev`:
005 и 008 отмечены выполненными в `tasks/todo.md` и содержат отчёты о ревью и
проверках; 007 также выполнена. Ветка `feature/009-available-slots` создана от
`origin/dev` (`ad5ad55`). Наличие исходных файлов само по себе не считалось
подтверждением завершения зависимостей.

Владелец 06.10.2026 подтвердил сохранение согласованного публичного контракта.
`docs/specs/availability.md` и `contract/main.tsp`
задают публичный `GET /api/v1/experts/{publicId}/slots` только с `from`, `to`
и `durationMinutes`; подтверждение гостя в нём не передаётся. Спецификация
прямо относит проверку занятости гостя после подтверждения email к подаче
заявки. Исходная цель этой карточки формулировала учёт занятости гостя при
подтверждённом email. PDR TIME-07/08, AC-06 и онтология §5.1 требуют
проверки этой занятости при подаче и подтверждении, а задача 010 ещё не
выполнена. Прямой API заявки и подтверждение относятся к 010/011; в 009
невозможно объявить AC-06 полностью проверенным без них.

В 009 публичная выдача проверяет расписание и занятость эксперта, включая
пересечения с его подтверждёнными встречами в обеих ролях. Персональная
занятость гостя проверяется по подтверждённому email в 010/011 при подаче и
подтверждении. Поэтому в 009 проверяются только относящиеся к выдаче части
AC-03/04/06/07; полный AC-06 и прямой API заявки требуют 010/011. PDR,
онтология и публичный контракт остаются без изменений.

Владелец 06.10.2026 разрешил точечно расширить область задачи на
`server/src/auth/index.ts` для регистрации публичного маршрута и
`server/src/repository.ts` для SQL-чтения подтверждённой занятости.

## Результат и проверка

Тестировщик до реализации зафиксировал Red: публичный GET вернул `404` вместо
`200` при ожидающей заявке. Последующие Red подтвердили ошибку фильтрации
`confirmed`, ответы `500` вместо `400` для неправильной длительности и даты,
а также две ошибки на границе повторяющегося часа DST. Один Backend-разработчик
реализовал выдачу и исправил найденные случаи. Исходный `origin/dev` содержал
незакрытую функцию `replaceScheduleRows` в `server/src/repository.ts`; для
запуска тестов восстановлена отсутствующая `}`. Ревьюер повторно одобрил код
после последнего DST-исправления.

После ревью Тестировщик независимо выполнил:

- `npm run test -w @mybooking/server -- tests/public-slots.test.ts --pool=threads` — 14/14;
- `npm run test -w @mybooking/server -- --pool=threads` — 16 файлов, 62/62;

Проверены AC-03 и AC-04 для публичной выдачи: части расписания и перерыв,
длительности и шаг, границы 24 часов и 30 суток, исключённая дата, DST gap и
обе ветви overlap. Для AC-06/07 проверена только часть публичных слотов:
`confirmed` эксперта в обеих ролях скрывает пересечение, `pending` не скрывает,
соседний подтверждённый интервал допустим. Публичный ответ не содержит
сведений о бронированиях. Занятость подтверждённого email гостя, прямой API
подачи и подтверждения, атомарное закрытие пересекающихся pending остаются в
010/011; полный AC-06/07 здесь не объявляется. Реальные письма, браузер и
контейнер в 009 не проверялись.

## Работа

Показать публичные свободные слоты без аккаунта с учётом расписания и
подтверждённой занятости эксперта. Занятость гостя по подтверждённому email
учитывается при подаче и подтверждении заявки в 010/011.

## Приёмка

Pending не скрывает публичный слот; confirmed эксперта в обеих ролях скрывает
пересечение. Прямой API заявки повторяет полную проверку в 010/011.

## Проверка

AC-03/04 и относящиеся к публичной выдаче части AC-06/07; Vitest и Fastify
inject. Полные AC-06/07 проверяются в 010/011.
