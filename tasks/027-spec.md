# 027 — Публичные слоты в интерфейсе: спецификация

Статус: согласовано владельцем для реализации 06.10.2026. Основание: [PDR §3, UI-05, AC-03/04/17](../docs/PDR.md), [DESIGN §"Публичная страница эксперта", §"Сетка и адаптация", §"Время, состояния и обратная связь"](../docs/design/DESIGN.md), [PRODUCT §"Product Purpose", §"Operating Context"](../docs/design/PRODUCT.md), [availability contract](../docs/specs/availability.md). Зависимости 009 и 017 подтверждены слиянием в `dev` и отчётами.

## Граница

Гость без аккаунта открывает личную ссылку эксперта и видит его имя, длительности 15/30/60 минут на выбор, выбранный гостевой пояс с возможностью смены и список свободных слотов в выбранном диапазоне дат. `pending` других гостей не скрывают слот. Прямая подача заявки и форма гостя относятся к задачам 028/029; в 027 реализуется только просмотр слотов с выбором.

Сервер уже выдаёт `GET /api/v1/experts/{publicId}/slots?from=...&to=...&durationMinutes=...` с `{timezone, slots: [{startAt}]}` и отвечает `400/404` на невалидный запрос или неизвестного эксперта (см. [contract/main.tsp](../contract/main.tsp) §`listSlots` и [availability.md](../docs/specs/availability.md)).

## Сценарии

### S1. Успешная выдача слотов

1. Гость открывает `/experts/{publicId}` без входа и cookie.
2. Страница показывает имя эксперта, выбранную длительность по умолчанию `30` минут, часовой пояс гостя по умолчанию — определённый браузером, и список свободных слотов за диапазон по умолчанию `30` суток вперёд.
3. Каждый слот показывает время в часовом поясе гостя с явным текстом «{time, zz}` ({IANA})» рядом; дополнительно показывается IANA-идентификатор эксперта.
4. Гость меняет длительность — список перезапрашивается и обновляется.
5. Гость меняет свой часовой пояс — отображение времени обновляется без перезапроса.
6. Гость кликает слот — слот получает признак «Выбрано» и доступную подпись; повторный клик снимает выбор.

### S2. Пустой результат

1. API возвращает `slots: []`.
2. Страница показывает явное состояние «Свободных слотов нет» с коротким пояснением, что делать дальше (например, выбрать другую длительность или зайти позже), и сохраняет структуру экрана с другими элементами.

### S3. Ошибка загрузки

1. API возвращает `5xx` или сеть обрывается.
2. Страница показывает `role="alert"` с русским текстом причины и кнопкой повтора, не блокирующей остальные элементы.
3. Пустое состояние и ошибка различаются не только цветом, но и текстом/иконкой/структурой.

### S4. Несуществующий эксперт

1. API возвращает `404 not_found`.
2. Страница показывает нейтральное сообщение «Страница не найдена» без раскрытия существования ссылки и без блокировки общей навигации.

### S5. Адаптивность

1. На ширине `1280px` и `390px` страница остаётся доступной: нет горизонтального скролла всей страницы; минимальная область нажатия для слотов и переключателей — `44×44px`; список слотов остаётся читаемым и доступным с клавиатуры.
2. На обеих ширинах управление и смена состояний работают клавишами `Tab`, `Shift+Tab`, `Enter`, `Space`.

## Инварианты

- `pending` заявки не скрывают слот: фронт отображает то, что вернул сервер, без дополнительной фильтрации.
- Пояс гостя виден явно на странице, рядом со слотом и в управлении выбором.
- Пояс эксперта виден отдельно и не погашается гостем.
- Состояние загрузки сохраняет структуру экрана с нейтральными заполнителями, а не пустую страницу.
- Тексты и сообщения — только на русском, кроме идентификаторов, имён файлов и тестов.
- Ответы API и серверная логика вне области 027; 027 ограничен файлами `web/src/` (страница, состояния, стили, API-клиент) и `e2e/src/` (тесты).
- Используется только согласованный стек; добавляется `@js-temporal/polyfill` в `web` только если без него невозможно корректно отобразить время в гостем в выбранном поясе с явным обозначением; иначе обходимся `Intl.DateTimeFormat` и `Temporal` через встроенные API браузера.

## Открытые решения, требующие явного выбора

- Точное имя маршрута: `/experts/{publicId}` против `/u/{publicId}` против другого. По умолчанию в этой задаче — `/experts/{publicId}`; альтернативы можно обсудить.
- Вид календаря: PDR §8 UI-05 требует «месяц со списком слотов и недельная сетка; переключение видов». В этой задаче реализован только месяц со списком; недельная сетка и переключение видов отложены и должны быть перенесены в отдельную задачу после согласования с владельцем. AC-17 в части «оба вида календаря» покрыт частично — только список. В PDR правок не вносилось; ограничение задокументировано TODO в `web/src/expert/PublicExpertPage.tsx`.
- `from`/`to` строятся в гостем поясе как приближение к поясу эксперта до первого ответа: ограничение 30-суточным горизонтом и явный комментарий в `PublicExpertPage.tsx`. Получение `timezone` эксперта до запроса слотов — задача для следующей итерации (например, вместе с публичным профилем эксперта).

## Проверка

- AC-03 — список слотов на 30-минутной длительности включает `09:00–09:30`, `09:30–10:00`, `10:00–10:30`; перерывы и длина шага соблюдены.
- AC-04 — окно запроса `from`/`to` ограничено 31 днём; старт менее чем за 24 часа скрыт сервером.
- AC-17 — адаптивность и клавиатура для ширин 1280 и 390.
- В Playwright проверяются: соответствие ответа API отображаемым слотам; явное наличие пояса гостя и эксперта; `pending` не скрывает слот; переключение длительности и пояса; пустой и ошибочный сценарии; адаптивность.
- API вызовы перехватываются через `page.route()` с фикстурой; поднимать серверный объект в e2e не требуется.
