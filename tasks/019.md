# 019 — Согласие и cookie в интерфейсе

Статус: выполнено 06.10.2026. Разработчик: Frontend. Зависит от: 006, 017.

Зависимость 006 подтверждена слиянием `feature/006-privacy-consent` в `dev` и наличием `server/src/privacy/index.ts` с маршрутом `GET /api/v1/privacy`. Зависимость 017 подтверждена слиянием `feature/017-web-foundation` и отчётом в [017.md](017.md) о зелёных проверках темы, клавиатуры и адаптивности. В ветке `feature/019-privacy-web` Тестировщик сначала зафиксировал ожидаемые падения шести Playwright-проверок (region/checkbox/dialog не найдены), затем Frontend-разработчик собрал блок согласия, модал документа и закрываемое cookie-уведомление. После одного цикла правок по перекрытию cookie-уведомления и поправки теста на видимость чекбокса в кабинете ревью одобрил изменения без дополнительных замечаний. Тестировщик выполнил итоговую проверку на компьютере и телефоне.

Итог на Node.js 24.14.1 и npm 11.11.0: `PLAYWRIGHT_BROWSER_CHANNEL=msedge npm run test --workspace @mybooking/e2e -- --reporter=line --workers=1` — 20 проверок прошли в Edge при ширине 1280 и 390 пикселей. Проверены видимость cookie-уведомления с упоминанием `mybooking_session` и отсутствием фиктивного выбора, отсутствие блокировки темы, навигации и согласия, закрытие уведомления и его сохранение после перезагрузки, изначально пустая галочка и её влияние на кнопку «Запросить код», доступность диалога документа с контактом удаления и краткое описание данных из API. Регрессия темы, фокуса, навигации и ошибки маршрута из задачи 017 не нарушена. `npm run typecheck --workspace @mybooking/web`, `npm run typecheck --workspace @mybooking/e2e` и `npm run lint` завершились с кодом 0. Prettier на изменённых файлах завершился без замечаний; общая `npm run format:check` показывает 58 ранее существовавших проблем вне задачи и не запускалась здесь.

Точные закреплённые версии Node.js 24.21.0 и npm 12.2.0 не были доступны; встроенный Chromium не установлен, поэтому браузерные проверки выполнены в Edge. Кнопка «Запросить код» формирует объект согласия для будущего вызова API из задач 018 (вход эксперта) и 028 (проверка email гостя); сам сетевой запрос к `/api/v1/auth/expert/challenges` и `/api/v1/experts/{publicId}/guest-challenges` здесь не выполняется, чтобы не выходить за область 019. Cookie-уведомление размещено в потоке страницы, а не фиксированным баннером: при ширине 390 пикселей оно перекрывало чекбокс согласия, поэтому для соблюдения AC-21 («не блокирует бронирование») выбрана инлайновая раскладка. Серверная часть не запускалась; в тестах используется `page.route` для мока `/api/v1/privacy`.

## Работа

Показать краткий учебный текст о данных и обязательную пустую галочку перед запросом кода. Добавить закрываемое информационное уведомление о необходимых cookie.

## Приёмка

Без галочки запрос кода недоступен; тексты доступны из формы; уведомление не блокирует бронирование и не содержит фиктивного выбора необязательных cookie.
