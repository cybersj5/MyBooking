# 005 — Проверка email гостя и ссылка

Статус: выполнено 06.10.2026. Роль: backend. Зависит от: 003.

Зависимость 003 подтверждена слиянием в `dev` и проверкой схемы. Тестировщик
зафиксировал Red для гостевого кода, восстановления доступа, незавершённого
профиля и первой ссылки. После исправлений повторное ревью требований и
соглашений одобрило код. Финальная проверка:

- `npm run test -w server -- tests/guest-auth.test.ts` — 5/5;
- `npm run test -w server` — 37/37;
- `npm run typecheck -w server` и `npm run lint` — код 0.

Проверены код и доказательство гостя без аккаунта, нормализация email,
самобронирование на границе `identity`/`bookings`, право токена на одну заявку,
истечение и отзыв ссылки, одинаковые ответы восстановления, доступ эксперта
только с завершённым профилем. Создание заявки, погашение доказательства в её
транзакции, первичное письмо и занятость AC-06 проверяются в задачах 010/011.
Реальная отправка через Gmail не проверялась.

## Работа

Проверить email гостя кодом без создания аккаунта; дать право на одну заявку через хеш защищённого токена.

## Приёмка

Чужая заявка недоступна по publicId и email; просроченный токен не работает; самобронирование запрещено.

## Проверка

AC-01/02; изоляция запросов Fastify inject.

## Область файлов

server/src/auth/, server/src/bookings/ (только `GET /api/v1/bookings/{bookingId}`),
server/src/repository.ts, server/tests/.

Владелец расширил область задачи 06.10.2026. Чтение заявки по согласованному
HTTP-контракту нужно для проверки доступа по токену через Fastify inject.
Создание заявки и её переходы остаются в задаче 010 и последующих задачах.

Код MVP выполнять только после отдельного разрешения владельца проекта. Изменения требований сначала согласовать и внести в PDR.
