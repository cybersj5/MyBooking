# Спецификация публичного HTTP-контракта `bookings`

Статус: публичная форма согласована владельцем 05.10.2026. Основание: [PDR §2–6, §10.1](../PDR.md), BOOK-01, AC-02/05–10/12; [ADR-002 «Идентичность и право доступа»](../ADR-002.md); [онтология §5–8](../ONTOLOGY.md); согласованные доказательства доступа [identity](identity.md).

## Граница

Публичная команда создания использует `guestProof` для выбранного эксперта; он погашается только после успешной заявки. Дальнейшее гостевое чтение и изменение требуют bearer `accessToken` одной заявки. Эксперт использует свою сессию; каждый объект проверяется на сервере. Чужая и отсутствующая заявка получают одинаковый `404 not_found`. Публичные ответы не содержат техническую очередь, хеши, токены другого участника и внутреннюю схему SQLite.

## Публичный HTTP-контракт

| Метод и путь | Основной вход | Успех | Доступ |
| --- | --- | --- | --- |
| `POST /api/v1/experts/{publicId}/bookings` | `guestProof`, `guestName`, `guestTimezone`, `startAt`, `durationMinutes`, `topic`, `description?`, `consentVersion`, `consentAccepted: true`; заголовок `Idempotency-Key` | `201` с ID, состоянием `pending` и публичными деталями своей заявки | Подтверждённый email для этого эксперта |
| `GET /api/v1/bookings/{bookingId}` | — | `200` с деталями одной заявки и её состоянием | Сессия её эксперта либо bearer-токен этой заявки |
| `GET /api/v1/me/bookings` | Query `from?`, `to?` как ISO 8601 со смещением, `status?`, `cursor?`, `limit?` | `200 {items, nextCursor}` со своими заявками и встречами | Сессия завершённого профиля эксперта |
| `POST /api/v1/bookings/{bookingId}/confirm` | `Idempotency-Key`, `X-CSRF-Token` | `200` с состоянием `confirmed` | Эксперт-организатор, Origin, CSRF |
| `POST /api/v1/bookings/{bookingId}/reject` | Причина?, `Idempotency-Key`, `X-CSRF-Token` | `200` с состоянием `rejected` | Эксперт-организатор, Origin, CSRF |
| `POST /api/v1/bookings/{bookingId}/withdraw` | Причина?, ключ идемпотентности | `200` с состоянием `withdrawn` | Гость с токеном заявки |
| `POST /api/v1/bookings/{bookingId}/cancel` | Причина?, `Idempotency-Key`; `X-CSRF-Token` обязателен при cookie-сессии эксперта | `200` с состоянием `cancelled` | Один из участников в пределах срока своей роли |

Состояния и системные причины берутся из PDR §5. Тема обязательна, до 120 символов; описание до 2000. Начало передаётся однозначным моментом со смещением; сервер сверяет расписание, 24 часа и 30 суток, а при подтверждении — срок 3 часа и занятость обоих участников. `Idempotency-Key` обязателен для создания и изменяющих команд по BOOK-01; повтор того же тела возвращает сохранённый результат, другое тело с тем же ключом даёт конфликт. Почта и SSE не являются частью синхронного ответа. Гостевой `accessToken` после создания отправляется только письмом и не входит в ответ `201`.

Ответ одной заявки содержит `id`, `status`, `startAt`, `endAt`, `topic`, `description?`, `guestName`, `guestTimezone`, `expertName`, `expertPublicId`, `closedReason?`, `completed` (вычисляется для прошедшей подтверждённой встречи). Эксперт-организатор дополнительно видит `guestEmail`; гостю email эксперта не выдаётся. В ответах `GET /api/v1/me/bookings` те же поля и только заявки этого эксперта как организатора. `limit` по умолчанию 20, допустимо 1–50; `nextCursor` — непрозрачная строка либо `null`, сортировка по началу от раннего к позднему. `from` включительно, `to` исключительно.

Некорректная форма получает `400`; нет права — `401` либо одинаковый `404 not_found` для чужой и отсутствующей заявки; незавершённый профиль — `403 profile_incomplete`; неверное состояние, срок, занятость или повтор ключа с другим телом — `409` с безопасным кодом причины. Открытые секреты и чужие сведения в ошибку не включаются.
